## 1. Aff3DFunc 给了三条可迁移的，也指出一条冲突

### 1.1 可迁移（直接采纳）

**① 四视角概念池。** 论文把描述限制在四个视角以抑制 LLM 幻觉、控制不确定性：

| 视角 | 含义 | 我们的现状 |
|---|---|---|
| action 动作 | 能对物体做什么 | ❌ 缺失 |
| function 功能 | 物体相对该可供性发挥的作用 | ❌ 缺失 |
| appearance 外观 | 与动作/功能相关的视觉特征 | ✅ 现有 24×4 全部属于此视角 |
| environment 环境 | 交互可能发生的场景条件 | ❌ 缺失 |

现有描述池实测（`grasp`）：`narrow part a hand can close around` / `protruding handle` / `flat rim to pinch` / `recessed undercut to hook` —— 四条全是形态变体，是**同一视角内的机制枚举**，不是多视角覆盖。

**② 信息瓶颈的两把标尺（把不可算的互信息换成可测量）。**

$$S^{*}=\arg\max_{S'\subseteq S} I(A,S')-\beta\,I(S';S) \quad\Rightarrow\quad \mathrm{Score}(S)=\alpha\,\tilde{V}(S)+(1-\alpha)\,\tilde{U}(S)$$

- $\tilde V(S)$：**类内方差**，近似「提升与可供性的互信息」
- $\tilde U(S)$：**类间可分性**，近似「压低与原始概念集的冗余」

工程含义：描述池的好坏从「写得像不像」变成**可在线测量、可画散点图、可调参**的量。这正是我们目前缺失的——96 条描述写完就直接跑，没有任何量化体检。

**③ 池大小有边际衰减。** 论文实测：4 条 → 方差 0.2889 / 可分性 0.1339；64 条 → 0.3463 / 0.1331；100 条 → 0.3537 / 0.1329。**扩大池主要抬方差，对可分性几乎无益甚至微降。** 结论：不必堆池大小，视角覆盖比条数重要。

### 1.2 冲突（必须做实验回答，不能照抄）

论文表 4「短语融合」：**先拼接再编码优于逐条编码再池化**，mIoU 0.2942 对 0.2747；原因是逐条编码池化把归一化方差从 **0.58 压到 0.29**、类间可分性从 **0.34 压到 0.13**——同时损掉多样性与区分度。

我们的 V1-A 描述支路正是**逐条 `encode_pooled` 再聚合**。所以论文这组数据是对着我们的设计来的。

**但有一个关键差别：论文批评的是均匀池化，我们是几何条件加权。**

- 均匀池化：4 条压成一个平均向量 → 所有区域看到同一向量 → 方差必然坍缩
- 条件加权：每个区域按自身几何取不同权重 → 不同区域看到不同的描述组合 → 理论上能保留甚至放大方差

这不是自我安慰，而是**可证伪的**：在线计算「加权后描述嵌入的类内方差」，若 conditional 显著高于 mean，则论文的结论在我们这条路上不成立；若相当，则应当改用拼接。

**这条也正好是笔记末尾给的建议**：可辩护的差异点应落在「让概念池的采样权重随几何侧观测质量变化」，而不是再提一种采样启发式——我们的区域条件选择器正是这个位置。

### 1.3 Aff3DFunc 同时化解了「标签 vs 问句」的纠结

论文是**以标签为索引查概念池**，但标签只作索引键，模型输入是**丰富后的功能文本**。这印证了 v1 §3.C 的判断：索引走标注 ≠ 标签泄漏，因为供给模型的信息量完全不同。

论文表 4 同时显示：只用标签 0.1741 → 简单提示 0.2145 → 完整四视角流程 0.2942。说明**即使有 FTE，输入文本本身的丰富度仍独立贡献**。因此我们两条文本流并存是合理的，且比论文更丰富：

- `text`（查询流）→ 走问句（v1 已定）
- `descriptions`（先验流）→ 走四视角功能文本（本次增强）

## 2. 改造清单

### 2.1 描述池升级：`configs/description_bank_v2.json`

**结构**（24 affordance × 4 视角 × K 条）：

```json
{
  "version": "v2-fte",
  "views": ["action", "function", "appearance", "environment"],
  "entries": {
    "grasp": {
      "action":      ["...", "..."],
      "function":    ["...", "..."],
      "appearance":  ["...", "..."],   // 复用现有池
      "environment": ["...", "..."]
    }, ...
  }
}
```

- **appearance** 直接从 v1 池取前 K 条（已验证可用，不重写）
- **action / function / environment** 按 affordance 语义新写
- 规模建议 **K=2 → 8 条/类（192 条，需新写 144 条）**；K=3 → 12 条/类（288 条，新写 216 条）
- 依据 §1.1③：池不必大，K=2 足够，**推荐 K=2**

`description_bank.py` 相应扩展：按视角分组加载、`get_padded` 仍返回定长 M 条 + valid，新增 `view_ids`（每条描述属于哪个视角）便于诊断与按视角消融。

### 2.2 新增离线评估脚本 `tools/eval_description_bank.py`（IB 两把标尺）

用**冻结的 RoBERTa**（与训练同一权重）编码全池，计算并输出：

| 指标 | 定义 | 用途 |
|---|---|---|
| $\tilde V$ 类内方差 | 同类描述嵌入两两余弦距离均值，跨类平均后归一化 | 多样性 |
| $\tilde U$ 类间可分性 | 类中心最近邻间距 / 类内半径，归一化 | 区分度 |
| Score | $\alpha\tilde V+(1-\alpha)\tilde U$，默认 α=0.5 | 单值排序 |
| 分视角表 | 每个 affordance × 每视角的 (V, U, Score) | 定位哪类/哪视角最弱 |
| 池大小曲线 | M=4/8/12/16 时的 V 与 U | 复现论文边际衰减，定 M |

产物：`results/description_bank_v2_report.md` + CSV + 可选 t-SNE 图。**训练启动时打印该池的 V/U/Score**，写进 tensorboard `Desc/V`、`Desc/U`。这样换池立刻能看出是否更可分。

### 2.3 新增 concat 编码档（回应 §1.2 冲突）

现有描述支路：M 条逐条 `encode_pooled` → `[B,M,768]` → 区域条件加权。

新增分支：把 M 条**拼成整句**再编码 → `[B,768]`（广播给所有区域），即严格复现 Aff3DFunc 的 FTE。

配置项：`model.description_branch.encoding: 'pooled' | 'concat'`。

### 2.4 在线方差诊断（证伪 §1.2）

在训练循环里，用当前 batch 的 α 计算**加权后描述嵌入的类内方差** $\tilde V_{\text{online}}$，按 `mean` / `conditional` 分别统计并写 tensorboard `Desc/online_V`。

判据：
- $\tilde V_{\text{online}}^{\text{cond}} \gg \tilde V_{\text{online}}^{\text{mean}}$ → 条件加权确实保住了方差，论文的池化批评不成立
- 两者相当 → 应改用 concat，B3 会赢

这条诊断把「我们和论文谁对」变成一个训练中就能看到的数字，而不是跑完 100 epoch 猜。

### 2.5 配置与消融矩阵

| 档 | text 查询流 | 描述池 | 编码 | 聚合 | 回答什么 |
|---|---|---|---|---|---|
| **B0** | 问句 | 无 | — | — | 问句查询基线 |
| **B1** | 问句 | v2 四视角 | pooled | mean | 接入描述池值多少（≈论文的池化） |
| **B2** | 问句 | v2 四视角 | pooled | **conditional** | 区域条件选择值多少（我们的主张） |
| **B3** | 问句 | v2 四视角 | **concat** | mean | 严格复现 Aff3DFunc FTE |

- **B1 vs B3** = 「池化 vs 拼接」，复现论文结论
- **B2 vs B1** = 「区域条件选择」的净贡献（v1 已有）
- **B2 vs B3** = 我们的主张 vs 论文主张，正面回答 §1.2

其余超参与 v1 三档逐字一致；`name:` 用 `las_v1a_fte_b{0..3}`。
